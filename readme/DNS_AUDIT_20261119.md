# DNS 与订阅连通性排查

## 本次用户反馈的结论

iQOO Neo9 / Android 16，安装包 1.1.4-rc.1+2026111902。读取运行中的内核、节点元数据和日志，没有代替用户修改 VPN、DNS、代理选择或系统设置。

| 用户操作与实际路径 | 结果 |
|---|---|
| 原订阅，前置代理开启 | 31 个节点带有同一个香港 Hysteria2 前置；美国节点测速超时，用户确认网页打不开 |
| 启用用户提供的脚本 | 节点改名，原前置名称不存在，中转被现有配置生成器跳过；美国 Hysteria2 两个 HTTPS 测速目标分别为 243 / 258ms，用户确认网页可用 |
| 仅关闭脚本，DNS 不变 | 前置中转恢复，同一美国节点再次超时，用户确认网页打不开 |
| 用户关闭前置／链式代理，保持脚本关闭和 DNS 不变 | 用户确认网页恢复；补读控制器时连接关闭，没有取得这一状态的延迟数值 |

香港前置节点自身的独立测速也在 6.5 秒超时。因此，这次“脚本才能用”的主因是不同的中转路径，不能据此认定是订阅凭据或 DNS 默认服务器错误。没有自动更换前置、选择备用节点或修改用户选择。上述三个 API 测速阶段均核对手动 Selector 的选择未被诊断改变。

现有前置配置按节点名称引用；脚本改名后可能跳过旧引用。需要用户重新选择所需前置，不能把脚本开启后的可用性当作原链路恢复。

## 同时修复的独立源码问题

1. DNS 覆写使用默认设置时，旧逻辑仍优先保留订阅的公共节点解析器，实际配置与用户选择不一致。现在覆写开启时使用应用设置；关闭时保留订阅，私有节点解析器的兼容处理保留。
2. 关闭 DNS 覆写时不再无条件删除订阅 `fallback-filter.geosite`，保留订阅原有 DNS 过滤语义。
3. 删除应用层把节点 `server` 域名改成 hosts 中第一个 IP 的处理。由 Mihomo 原生 hosts 解析负责寻址，保留原域名供 TLS/SNI 验证和多地址选择。

第三项不是本次订阅故障的原因：该订阅没有 hosts。没有加入默认 DNS fallback、绕过证书校验或修改协议。

当前应用默认主解析器为 Alidns / DNSPod DoH；节点解析器为这两组 DoH 的 `#DIRECT` 形式。关闭覆写且订阅启用 DNS 时保留订阅 DNS；订阅没有启用 DNS 时才使用系统解析兼容模式。先前报告中的示例公司域名、`* → system` 和旧默认服务器不代表本分支当前实现。

## 验证与边界

- 32 项定向测试通过，2 项需显式启用原生脚本 DLL 的场景未在本次命令运行。覆盖 DNS 默认迁移、hosts、节点解析器、Android / Windows / Linux / macOS 配置生成和订阅切换。
- 真实 Windows Go 内核 + 回环 TLS 代理：旧 IP 改写配置失败；保留域名后 41ms 成功；错误域名仍失败。三种配置均保持证书验证开启，夹具证书只加入临时内核的信任池，没有修改系统证书。
- 手机 shell 向两组 UDP DNS 和两组 DoH 查询均成功；不是“所有这些 DNS 在当前网络均不可达”。
- 电脑运行着另一套 TUN，且物理 WLAN 没有可用 IPv6。因此电脑全节点失败不能作为手机或客户端差异的有效对照。
- 临时 Linux arm64 shell 内核不能等同 Android 应用网络环境：IPv6 连接报 network unreachable。隔离脚本夹具还缺少 rule-set 引用，未完成全量脚本集成。临时设备目录已清理，没有改变手机路由或 VPN。
- 本次新增 DNS 代码尚未安装到手机验证；Windows 回环与四平台配置测试不能冒充跨平台实网验证。
- 私有订阅、凭据、节点详情和诊断日志只保存在本地忽略目录，不进入提交。

## 回滚

撤回本次 DNS 源码及对应测试即可恢复此前生成逻辑。用户原始订阅、脚本和前置代理配置均未被这些代码修复重写。
