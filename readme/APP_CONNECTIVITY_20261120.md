# 策略组测速与首页检测重试

版本：1.1.4-rc.1+2026112001。

DNS 和用户订阅的手机对照结论见 [DNS 审计](DNS_AUDIT_20261119.md)。本次未修改 Go 内核、热点共享或用户原始订阅。

## 改动

- GLOBAL 等列表中的现有 Selector、URLTest、Fallback、LoadBalance 参与批量和单次测速。按策略组本身向内核发请求，显示自身结果；不会把负载均衡组的首个成员误报为整个策略组的延迟。没有新增任何故障转移策略。
- 代理卡片、链式／WARP／前后置选择器使用一致的结果。排序与超时软隐藏优先读取对象自己的测量，未测时保留原有成员结果展示。
- 路径改变、配置重新应用时清除旧策略组测量；旧请求不回填到新路径，同名新请求也不复用旧路径的在途请求。隐藏策略组同样受保护。普通节点历史保留，现有并发上限不变。
- 首页增加可见的“重试”，检测中禁用重复点击并显示进度。恢复成功后更新状态，不重启核心或改变节点。保留原有核心重启、暂停和选择节点入口。
- 检测支持配置中有效的 HTTP / HTTPS 目标；无效地址和端口给出可重试失败，不再停在未检测状态。新检测、停止或重启会关闭旧检测连接，旧结果不覆盖新状态。仍通过本机实际混合端口检测，HTTPS 证书校验和禁止跟随登录页重定向保留。
- 大字号窄屏保持电源按钮在状态区，避免挤掉底部节点名称；减少动效模式使用静态等待图标。

## 验证

- 85 项合并定向回归通过，含真实 Rust 脚本 DLL、四平台配置生成、订阅切换、DNS、策略组测量、测速并发、延迟稳定性和首页操作。
- 最终边界调整后 32 项复测通过，覆盖隐藏策略组、切换路径时的在途结果隔离、策略组自身延迟与超时过滤、HTTP 代理请求、重定向拒绝、取消回收、首页失败→重试→成功。与上一组有重叠，不能相加计算总测试数。
- 两项完整首页“搜索节点→选择→显式启动→检测失败→重试”流程通过，窗口分别为 390×844 和 1280×900。
- 真实桌面 Go 内核回环：四种现有策略组均成功返回延迟，约 1ms；只验证调用路径和结果，不代表公网性能提升。
- 查看浅色／深色代理卡片的成功和超时，以及首页窄屏大字号／桌面失败和恢复截图。点击测速、重试主流程已走通。这些是 Flutter 主机渲染，未冒充手机安装包验收。
- `flutter analyze --no-pub` 无问题，`git diff --check` 通过。

原始日志在忽略目录 `build/dns-diagnostics/`，组件截图在 `build/feedback_fixes/screenshots/`。私有诊断资料不提交。

## 限制与回滚

新安装包尚未在手机和各桌面系统安装验收；公网测速、不同系统 TLS 环境和实际代理链可用性仍取决于用户网络与配置。首页检测是指定测速地址的可达性检查，不能保证所有网站可用。

撤回本次提交可恢复原界面和测速逻辑；未迁移或删除用户数据。应用提交独立于未提交的内核优化候选。
