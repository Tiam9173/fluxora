# 脚本配置加载与订阅切换

## 修复范围

相同脚本产生的 HTTP 规则集原来按订阅分别缓存。新订阅没有自己的缓存时，内核必须等待重复下载，再返回代理组。现在仅复用相同规则资源的原始文件，代理节点、脚本输出和订阅内容不共享。

缓存键包含规则提供者除路径以外的完整配置和全局 User-Agent，使用 SHA-256。URL、请求头、代理、格式、行为、更新间隔等条件不同会隔离；字段顺序不同可能少一次缓存命中，不会错误复用。旧缓存复制到新位置时保留修改时间，过期更新仍由内核负责。迁移失败使用原路径，不阻断配置应用。聚合规则路径同步适配。

脚本输入的 JSON 编码移到后台 isolate。脚本仍每次重新运行，保留 Promise、选项、错误、时间和内存限制。配置生成、内核应用和脚本各阶段增加耗时日志，不记录配置、URL 或凭据。

没有移植另一套内核配置构造流程，没有新增 Go 补丁或热点代码。

## 实测

Windows amd64，Go 1.25.14，本分支原有 Go 源码构建的桌面桥接内核；二进制 SHA-256：`574fae6b6568449a68a9c616b6de269b22bcce776b6dc8e300ac503341a3c81a`。

真实 Rust 脚本生成运行配置，真实内核应用、读取规则文件并返回新节点。A/B 对照只改变规则缓存路径；本地规则服务器固定延迟 800ms，顺序 ABBA，每种路径 8 次切换：

| 指标 | 原路径 | 复用缓存 |
|---|---:|---:|
| 内核应用至新节点可读，中位数 | 829.305ms | 2.136ms |
| 范围 | 822.104–836.765ms | 1.710–2.500ms |
| 切换产生的规则下载次数 | 8 | 0 |

首次冷加载仍约 0.82 秒，需要获取规则。过期缓存触发后台下载，保持规则新鲜度。这是受控下载场景，不能解释为所有订阅、脚本或网络都能在 2ms 加载。

Flutter 主机测试（JIT），1 万节点、10 万规则，交替测量输入编码：同步编码事件循环最长间隔 29.6–32.2ms，后台编码为 9.0–11.8ms。编码总耗时约 24.8–26.8ms → 32.5–33.3ms；收益是减少界面阻塞，并非编码更快。20 节点、千节点及真实原生脚本均检查输出节点、规则数量和选项。

## 限制与回滚

真机、用户完整订阅及公网规则源耗时 NOT VERIFIED。首次新增规则、清除数据或恢复未包含规则缓存的备份后，仍需正常下载。不可达规则源、脚本自身重计算和第三方服务器等待需要依据新增阶段日志继续定位。

撤回本次提交即可恢复原编码及按订阅缓存路径；旧缓存未删除，原订阅和脚本文件未重写。共享缓存可重建，不应手动删除正在使用的规则文件。
